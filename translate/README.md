# Translations

The widget is translated with gettext/KI18n, the same way every Plasma applet
is. A plasmoid's own catalogue is looked up under the domain
`plasma_applet_<plugin id>`, which for this widget is
`plasma_applet_org.deepseek.plasma.usage`, in the package directory

```
contents/locale/<locale>/LC_MESSAGES/plasma_applet_org.deepseek.plasma.usage.mo
```

so no system-wide installation is involved.

## Layout

| Path | Role |
|---|---|
| `template.pot` | Extracted from the sources. Generated by `merge.sh`, committed. |
| `messages/<locale>.json` | **Source of truth** for our translations. One table per locale, or a small override table on top of a base locale. |
| `generate.mjs` | Builds `<locale>.po` from `template.pot` + the tables. |
| `<locale>.po` | Generated. Committed, because it is the format every translation tool and every KDE translator expects. |
| `LINGUAS` | The list of locales we ship. |
| `crowdin.yml`, `.tx/config` | Ready-made configs for handing the catalogue to an online platform. Unused unless you choose that route; see below. |
| `../contents/locale/**/*.mo` | Compiled catalogues, committed so `./install.sh` works without gettext. |

## Workflow

```sh
./translate/merge.sh     # after changing i18n() calls: refresh template.pot
$EDITOR translate/messages/xx.json
./translate/build.sh     # regenerate *.po and compile *.mo
./translate/build.sh --check   # CI: fail if anything is out of date
```

`merge.sh` parses QML with the C++-like parser and the `js/` modules with the
JavaScript parser, because gettext needs a different parser per language. It
also emits the `#:` references as repo-relative paths.

`generate.mjs` refuses to write a catalogue that would fall back to English at
runtime or break a format string. These are hard errors:

- a msgid in the pot with no translation (and no base catalogue),
- a plural entry whose variant count disagrees with the locale's
  `Plural-Forms`,
- a translation that drops or invents a `%1`-style placeholder.

`msgfmt --check --check-format` is run again by `build.sh` as an independent
check.

## Table format

Keys are **gettext keys**, the same ones gettext uses internally:

```
[msgctxt + U+0004] + msgid [+ U+0000 + msgid_plural]
```

so `"token usage table row\u0004Cost"` is the entry for `i18nc("token usage
table row", "Cost")`, and `"Last %1 day\u0000Last %1 days"` is the plural entry.
Values are strings, or arrays with one element per `Plural-Forms` variant
(1 for zh_CN/id_ID, 2 for hi_IN/fr_FR/es_*, 3 for ru_RU/ru_BY).

A table with a `base` key starts from another locale and applies its own
`overrides`. Two aliases exist because Qt looks up `<lang>_<REGION>` and then
bare `<lang>`, so the bare entries widen coverage at no cost:

- `es_CL`, `es_AR`, `es_MX`, `es_CU` are aliases of `es_419`. This is
  deliberate: **none of the current strings differ between them.** If one ever
  does, give that locale its own `base` + `overrides` and it stops being a copy.
- `es_ES` inherits `es_419` and overrides the handful of strings where Spain
  differs (`ajustes` vs `configuración`, `importes` vs `montos`, …).
- `ru_BY`, `ru`, `fr`, `id`, `hi` are aliases of their regional catalogue.
- `en_IN` is an identity catalogue (each msgstr equals its msgid).

## Submitting through a translation platform

`template.pot` and the generated `.po` files are the standard formats, so the
catalogue can be handed to an online platform without changing anything here.

Which one, honestly:

- **KDE's own infrastructure** is the most idiomatic route for a plasmoid:
  KDE translates applet catalogues through its l10n team, and the KDE ecosystem
  uses WebLate. If this widget ever lands in an official repository, that is the
  path that gets real native translators.
- **Transifex** states on its open-source page that it is free forever for
  projects whose source is public, OSI-licensed and has *no funding, revenue or
  commercialisation model*. This project is GPL-2.0-or-later and unfunded, so it
  would qualify.
- **Crowdin** has an open-source programme too, but I could not verify its
  current terms (the page I fetched returned 404), so treat `crowdin.yml` as a
  starting point rather than a tested setup.

Neither `crowdin.yml` nor `.tx/config` has been run — creating the project,
applying for the open-source plan, choosing languages and inviting translators
are human actions I cannot do for you. They are checked in so the hand-off is a
few minutes rather than an afternoon.

> **Pick one source of truth.** Today `messages/*.json` is authoritative and the
> `.po` files are generated. If you start round-tripping through a platform, the
> `.po` files become authoritative instead: delete `messages/`, stop running
> `generate.mjs`, and keep `merge.sh` (to refresh `template.pot`) and `build.sh`
> (to compile). Nothing else depends on the tables.

## Status

**Every catalogue here is machine-generated and has never been reviewed by a
native speaker.** It is marked as such in the `Last-Translator` header and at
the top of each `.po`. Treat it as a solid starting point, not as finished
translation — this is exactly the work worth offloading to a platform or to a
native reviewer, and Hindi, Russian and Chinese are the ones to prioritise.

Harmless, expected `msgfmt` warning:

```
warning: header field 'Language-Team' still has the initial default value
```

That is gettext's placeholder for "no team has claimed this file yet", which is
accurate. It disappears once a real translation team adopts a catalogue.
